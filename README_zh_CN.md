# 掘金同步（思源笔记插件）

把思源笔记的文档一键同步为**掘金草稿**，自动把 `assets/` 里的本地图片转存到掘金图床；
并可选地把掘金文章反向导入成本地笔记。

> **本插件与掘金官方无关。** 它使用掘金**网页端私有接口**，凭证是从你自己浏览器里复制的
> Cookie。接口随时可能变更或下线，高频调用也可能触发平台风控。
> 配置凭证前请先阅读[风险声明](#风险声明)。

---

## 功能

| 能力 | 说明 |
| --- | --- |
| 正向同步 | 文档 → 掘金**草稿**（标题、摘要、分类、标签、正文） |
| 图片转存 | 逐张读取 `assets/…` 图片二进制，上传到掘金图床（字节 ImageX，SigV4 + CRC32 签名），并原地替换正文链接 |
| 防重复 | 文档与文章的映射写入块属性（`custom-juejin-*`），同一文档再次同步会**更新同一篇**，不会产生重复文章 |
| 默认安全 | 默认只建草稿；切换为公开发布后每次同步仍需二次确认 |
| 显式降级 | 思源专有语法（块引用、IAL、超级块、数据库块、挂件……）降级为可读文本，并在结果面板给出计数 |
| 反向导入（P2） | 粘贴 `https://juejin.cn/post/<id>` 链接，预览后选择目标笔记本，正文与图片一起落到本地 |
| 国际化 | 中文 / 英文两套界面文案（`zh_CN`、`en_US`） |

## 环境要求

* 思源笔记 **3.8.5 及以上**（使用 `saveData(storageName, content)` / `loadData(storageName)` 双参形态）
* 掘金账号，且已在掘金网页端创建过**至少一个分类**和**至少一个标签**

## 获取凭证

1. 用桌面浏览器登录 <https://juejin.cn>。
2. `F12` → **Application** → **Cookies** → `https://juejin.cn`。
3. 复制 `sessionid_ss`（或 `sessionid`）的值。
4. 回到思源：**设置 → 掘金同步** → 勾选风险确认 → 粘贴 → **测试连接** → **拉取分类与标签** → 选择默认分类与至少一个标签 → **保存**。

推荐做法：把 Cookie 存到思源「设置 → 密钥和变量」的密钥里，名称用 `juejin-sessionid-ss`。
插件会优先读它，界面上如实标注为「已存入思源密钥库」。
注意：插件 API 只能**读**密钥、无法替你创建，所以在插件设置页直接粘贴的值
「以明文保存在本地数据目录」，界面同样如实标注，不粉饰存储形态。

## 使用

* 文档标题左侧的图标（编辑器左上角 `📄`）→ **同步到掘金**
* `Dock` 面板 → **同步** tab → 「同步当前文档」
* 命令面板 → 「同步当前文档到掘金」（快捷键 `⌥⌘J`）

首次同步会弹出元信息确认框（标题 / 摘要 / 分类 / 标签）。摘要是**可编辑**的，按
**Unicode 码点**计数，输入框右上角实时显示 `N/100`；少于 50 或多于 100 时确认按钮会被禁用。
确认后在掘金创建草稿。

结果面板的排布是固定的：**没能转存的图片清单永远在最顶部、展开、不可折叠**，
下面是状态、图片统计、降级计数与警告；掘金返回的原始错误单独放在最底部的折叠块里，
原文透传不改写。清单非空时可以直接点「仅重试失败图片」，只重传失败的那几张并更新同一篇草稿。

到掘金网页端微调排版后自行发布。

反向导入：`Dock` 面板 → **从掘金导入** tab → 粘贴链接 → 「解析链接」→「读取文章」→
选择目标笔记本与路径 → 「导入到思源」。若私有接口拿不到正文，会自动降级为解析文章页面，
并在预览处直接标注「已降级为页面解析，可能丢失公式/代码高亮」。

### 降级规则

| 思源语法 | 处理方式 |
| --- | --- |
| 块属性 `{: id="…" }`、IAL | 直接删除 |
| 块引用 `((id "文本"))` | 替换为纯文本 |
| 文档引用 `[[id]]`、`siyuan://` 链接 | 替换为纯文本 |
| 超级块 / 挂件 / 数据库块 / `iframe` / 视频 / 音频 | 替换为 `> [思源 X 块，暂不支持同步]` 占位提示 |
| 本地图片 `assets/…` | 上传后替换为掘金 CDN 地址 |
| 外链图片 `![](https://…)` | P0 **保留原样**并给一条警告（掘金有防盗链，可能显示不出来） |
| 脚注、行内扩展语法 | 掘金能识别就保留，不能则降级为纯文本 |

## 风险声明

1. **私有接口。** 掘金没有开放的发布 API，全部能力都依赖网页端会话 Cookie。掘金一改接口，
   插件就可能失效。设置页高级分组里的「接口自检」按钮会告诉你具体哪个接口不通。
2. **账号风险。** 插件只做你显式触发的操作，请求串行并设有最小间隔，`4xx` 不自动重试；
   但风控是平台侧决策，插件无法保证不触发。
3. **凭证安全。** Cookie 等同于账号权限。它只保存在本地思源数据目录，插件不会上传到别处。
   「清除凭证」按钮可一键删除。
4. **内容保真。** 思源的 Kramdown 语法比掘金能渲染的更丰富。插件会显式降级（绝不静默丢内容），
   并默认只建草稿，让你发布前先看一眼。
5. **反向导入版权。** 只导入你自己写的文章。插件不提供批量、爬取能力。

## 开发

```bash
npm install        # 仅 devDependencies，运行时零第三方依赖
npm run build      # tsc --noEmit + vite build → dist/
npm run test       # vitest（仅纯函数，不依赖网络）
npm run check      # 只跑类型检查
npm run test:i18n  # 只跑三条 i18n 门禁（key 对齐 / 零中文硬编码 / plugin.json 口径）
```

`dist/` 产物：`index.js`、`index.css`、`plugin.json`、`icon.png`、`preview.png`、
`i18n/zh_CN.json`、`i18n/en_US.json`、两份 README。

软链到思源插件目录：

```bash
ln -s "$(pwd)/dist" ~/SiYuan/data/plugins/siyuan-juejin-sync
```

`npm run dev` 为 watch 构建（`vite build --watch`）。

## 已知限制

1. **插件无法感知你在网页端的发布动作。** 正向同步只在本地块属性里记录状态；如果你在掘金
   网页端把草稿发布了，插件仍然认为它是草稿，下次同步会去更新一篇已发布文章，掘金会拒绝
   （此时插件会把状态标为「状态未知（可能已在掘金发布）」并提示你到网页端确认）。
   Dock 状态区与同步确认框在状态为「草稿」时也会常驻一行提示。
2. **重复导入的「覆盖」依赖 `POST /api/block/updateBlock`。** 若内核拒绝该块类型，插件会
   退回「新建一篇文档」并在日志里说明原因，导入本身仍然成功。
3. **不支持思源超级块 / 数据库块 / 挂件块的原生还原。** 见上面「降级规则」。
4. **本仓库地址是占位值。** `plugin.json` 的 `url` 与 `author` 为示例，发布到集市前请替换为
   你自己的仓库地址与作者名。

## 尚未在真实环境验证的部分

下列各项需要**真实掘金账号**，开发阶段无法联调。每一项都有明确的失败分支与可读错误提示，
并且都在「接口自检」里有一条对应探针：

* `article_draft/create` 的 body 字段名（`edit_type`、`theme_ids` 等）：路由已证实，字段据推断。
* `article_draft/update` 的草稿 id 字段是 `id` 还是 `draft_id`：两种写法都会尝试。
* `article_draft/detail` 的入参形态。
* `article/publish` 的 body 与返回的文章 id 字段。
* `article/detail`：实测任意 id 都返回「404 内容为空」，因此反向导入会降级为从渲染页面
  （`__NUXT__`）提取 `mark_content`。
* ImageX 的 `ServiceId` / `uploadHost`，以及 SigV4 的 canonical request 是否只需签
  `x-amz-date;x-amz-security-token`。
* `forwardProxy` 在移动端是否可用（桌面端已实测可用）。
* 反向导入的「覆盖已有文档」走 `POST /api/block/updateBlock`（`dataType=markdown`）；
  若内核拒绝该块类型，会自动退回「新建一篇文档」并把原因写进日志，导入本身仍然成功。

诊断入口：所有探针都以可手动触发的函数形式实现（`JuejinApi.probeEndpoints()`），
插件更新后点一次「接口自检」就能看到掘金今天到底返回什么。
